# ЗЕРНО — генератор бесшовного шума для фона

Делает плитки шума, которые стыкуются друг с другом без видимых полос на стыке.
Считать может нативный сервер на Zig либо сам браузер.

Подробности реализации, найденные ловушки и замеры — в [how_it_made.md](how_it_made.md).

## Запуск

**С сервером (быстро, рекомендуется).** Двойной клик по `start.cmd` — он при
необходимости соберёт `zerno.exe`, откроет браузер и запустит сервер. Вручную:

```
zig build            собрать zig-out/bin/zerno.exe (по умолчанию ReleaseFast)
zig build run        собрать и запустить
zerno.exe --port 8787 --root . --cache-mb 256
```

Затем откройте http://127.0.0.1:8787/. Сервер слушает только петлевой адрес.

**Без сервера.** `index.html` открывается двойным кликом и работает сам —
тот же алгоритм на JS. Медленнее в 3–6 раз; в строке состояния так и написано:
`движок JS · браузер`. Ничего молча не подменяется.

```
index.html            разметка страницы и список подключений
static/css/           оформление: токены, база, каркас, компоненты
static/js/            движок и интерфейс на JS (запасной путь)
start.cmd             запуск сервера в один клик
build.zig             сборка
src/main.zig          HTTP-сервер, маршруты, кэш полей, раздача статики
src/engine.zig        шум, композит, дизеринг
src/color.zig         Oklab / OKHSL
src/doc.zig           модель документа и строгий разбор JSON
src/test.zig          тесты движка (zig build test)
src/bench.zig         замеры (zig build bench)
tests/                проверки на Node (node tests/run-all.js)
tests/load-app.js     собирает static/js/*.js в порядке из index.html
noises/               библиотека пресетов *.json, видна на странице
noises/index.json     список файлов; сервер поддерживает его в актуальном виде
```

## Скорость

Пресет «тёмный холст», 3 канала, AMD Ryzen 7 5800H (8 ядер / 16 потоков):

| что | JS в браузере | Zig |
|---|---|---|
| 512×512, правка цвета | 41 мс | **6.4 мс** |
| 512×512, пересчёт шума | 41 мс | **15.6 мс** |
| 1024×1024, пересчёт шума | 266 мс | **52 мс** |

Откуда взялось ускорение:

* **кэш шумовых полей** на сервере — правка цвета, формы или режима наложения
  не пересчитывает шум вовсе (это самый частый случай при работе руками);
* **пакетный запрос** — главная плитка и миниатюры всех каналов считаются
  одним запросом, а не по одному;
* **многопоточность** — поле строится полосами строк, композит тоже;
* предрасчёт по столбцам в горячем цикле и отсутствие целочисленного деления
  на каждый семпл.

Остаётся запас: композит с дизерингом стоит ~52 нс на пиксель и масштабируется
по потокам хуже, чем построение шума. Его можно ускорить векторизацией — сейчас
это не сделано.

## Один алгоритм в двух реализациях

Движок на Zig — дословный порт браузерного. Это проверяется автоматически:
оба считают одни и те же 10 пресетов и результаты сверяются попиксельно.
Максимальное расхождение — **1 младший бит** (следствие разного порядка
округления `f32`/`f64`), при выключенном дизеринге чаще всего 0.
Дизеринг сделан позиционным (значение зависит только от координат пикселя),
поэтому многопоточный расчёт даёт ровно ту же картинку, что однопоточный.

## Как устроена бесшовность

Каждое поле шума строится на решётке, у которой **число ячеек на плитку целое**.
Координата выборки `x = X · cells / W`, поэтому при `X = W` она равна ровно `cells` —
то есть ровно периоду решётки. Левый край плитки тождественно равен правому,
верхний — нижнему. Это выполняется для всех типов шума, для любого числа октав,
при искажении домена и при любом размере плитки, включая нечётный.

Свойство проверяется численно: средняя разность соседних столбцов на стыке
сравнивается с распределением таких же разностей внутри плитки. На стыке —
≈ 1× от 95-го процентиля (то есть ничем не выделяется), у заведомо непериодического
контрольного поля — 7×.

Вторая причина видимых полос — бэндинг при переводе в 8 бит. Его снимает дизеринг
(TPDF или Байер 8×8), причём шум не добавляется туда, где значение и так точно
ложится на 8-битный уровень: чистый чёрный и непрозрачная альфа остаются чистыми.

## Устройство документа

Плитка = **фон** (цвет без шума) + стопка **шумовых каналов** сверху вниз.
Каждый канал:

| | |
|---|---|
| **Шум** | тип, размер пятна по X и Y, сид, октавы, затухание, лакунарность, гребни, искажение домена |
| **Форма** | контраст, смещение, гамма, инверсия, нормализация диапазона |
| **Цвет** | два цвета OKHSL с альфой — «низ» (шум = 0) и «верх» (шум = 1); между ними интерполяция |
| **Слой** | режим смешивания (11 штук) и непрозрачность |

Типы шума:

* **Перлин** — облака, классический градиентный fBm;
* **Value** — мягче Перлина, менее «жилистый»;
* **Ворлей** — пятна и ячейки; режимы F1, F2, F2−F1 (трещины/сетка);
* **Зерно** — плёночное зерно; при ВЧ-фильтре > 0 становится «синим» шумом,
  который почти не даёт заметного повтора плитки.

Цвет везде задаётся в OKHSL (Björn Ottosson): H 0–360, S и L 0–1, плюс альфа.
Пространство подобрано так, что при любых S и L цвет остаётся внутри гамута sRGB —
клиппинга не бывает. Рядом с ползунками есть поле HEX для ввода готовых цветов.

Смешивание «низ → верх» по умолчанию идёт в OKLab (перцептивно ровное, без
грязных середин); переключается на линейный sRGB в разделе «Вывод». Режимы
наложения слоёв всегда считаются в линейном свете по формуле композитинга W3C.

## Библиотека пресетов из папки

Все `*.json` из папки показываются на странице миниатюрами. Источники, в порядке
предпочтения:

* **сервер** — при работе через `zerno.exe` библиотека берётся из `noises/`
  автоматически. Кнопка «Сохранить» кладёт туда текущий пресет, крестик на
  карточке удаляет файл, `index.json` сервер обновляет сам;
* **«Папка»** — File System Access API (Chrome/Edge, работает и с `file://`).
  Тоже с записью; папка запоминается между запусками;
* **«Обзор…»** — обычный `<input webkitdirectory>`, работает в любом браузере,
  но только на чтение;
* **`./noises/index.json`** — если страницу отдаёт обычный статический сервер
  (`npx serve .`, `python -m http.server`).

Файлы можно просто перетащить на страницу — это тоже импорт.

## HTTP API сервера

| метод | путь | что делает |
|---|---|---|
| `GET` | `/api/health` | движок, версия, число потоков, статистика кэша |
| `POST` | `/api/render` | `{"jobs":[{"width","height","doc"}]}` → сырой RGBA пачкой |
| `GET` | `/api/library` | все пресеты из `noises/` вместе с ошибками разбора |
| `PUT` | `/api/library?name=X.json` | проверить и записать пресет |
| `DELETE` | `/api/library?name=X.json` | удалить пресет |

Ответ `/api/render` — двоичный: `"ZRN1"`, `u32` число задач, затем по паре
`u32` ширина и высота на задачу, затем сами пиксели RGBA подряд. Некорректный
документ даёт `400` и то же самое сообщение с адресом поля, что и в браузере.

## Экспорт

* **PNG** — плитка как есть, с альфой (сделайте альфу фона < 1 для накладки);
* **WEBP** — качество настраивается, 1.00 в Chromium даёт кодирование без потерь;
* **JSON** — сам пресет;
* **CSS** — в буфер обмена уходит готовый блок с data-URI плитки и `background-repeat`.

## Проверка стыковки глазами

В панели над превью: **«Границы плиток»** рисует сетку по краям плиток,
**«Сдвиг ½»** сдвигает раскладку на половину плитки, чтобы стык оказался в центре
экрана. Масштаб 25–800 %, рядом — выбор цвета обрамления, чтобы судить фон
на светлом и тёмном.

## Формат JSON

Валидация строгая и без умолчаний: отсутствующее поле, лишнее поле, неверный тип
или значение вне диапазона дают исключение с точным адресом, например
`документ.channels[0].noise.shape.gamma: поле отсутствует (обязательное) [файл: my.json]`.
Файл всегда содержит полный набор полей, поэтому пресет переносится без потерь.

```json
{
  "format": "zerno-noise-tile",
  "version": 1,
  "name": "имя пресета",
  "tile": { "width": 512, "height": 512 },
  "render": {
    "stopMix": "oklab",
    "dither": { "mode": "tpdf", "amount": 1 },
    "webpQuality": 1
  },
  "background": { "h": 258, "s": 0.07, "l": 0.145, "a": 1 },
  "channels": [
    {
      "id": "clouds", "name": "Облака", "enabled": true,
      "blend": "normal", "opacity": 1,
      "noise": {
        "type": "perlin", "sizeX": 186, "sizeY": 186, "seed": 1337,
        "octaves": 4, "gain": 0.52, "lacunarity": 2, "ridged": false,
        "warpAmount": 38, "warpSize": 240,
        "worleyMode": "f1", "worleyJitter": 1, "grainHp": 3,
        "shape": { "contrast": 0.1, "bias": 0, "gamma": 1,
                   "invert": false, "normalize": true }
      },
      "low":  { "h": 266, "s": 0.24, "l": 0.04, "a": 0.34 },
      "high": { "h": 198, "s": 0.30, "l": 0.60, "a": 0.13 }
    }
  ]
}
```

Допустимые значения: `type` — `perlin | value | worley | grain`;
`worleyMode` — `f1 | f2 | f2f1`; `stopMix` — `oklab | srgb-linear`;
`dither.mode` — `tpdf | ordered | off`; `blend` — `normal, multiply, screen,
overlay, hard-light, soft-light, add, subtract, darken, lighten, difference`.

## Ограничения, о которых приложение говорит вслух

* Ячейка решётки мельче 2 px вырождает градиентный шум (у Перлина значение в узлах
  тождественно ноль), поэтому минимальное пятно для Перлина/Value/Ворлея — 2 px.
  Для попиксельного шума есть тип «Зерно», он рассчитан на 1 px.
* Число октав ограничивается сверху тем же правилом. Если запрошено больше,
  чем помещается, карточка канала показывает, до скольких октав ограничено и почему.
* WebP кодируется средствами браузера; если браузер не умеет — кнопка скажет об этом,
  а не сохранит молча PNG под именем `.webp`.
